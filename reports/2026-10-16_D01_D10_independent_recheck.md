## 三、实现可靠性审查（Standards）

标准来源为原方案的事务、基线身份、不可变制品、任务边界和持久化执行约定。无额外仓库编码标准时，不以个人风格偏好判错。

### S01 [P1] 新基线仍复用旧审核身份，旧请求可操作新记录

**位置：** `src/bio_pdf/storage/repository.py:1001`；`src/bio_pdf/review/plan.py:78–80`；决定入口的基线检查。

虽然新增了 baseline_id 和 superseded 状态，review_id 仍由 job、record、revision 派生，发布时 ON CONFLICT 又将同一 review_id 重绑定到新基线。决定接口只检查 record revision，无法识别旧页面提交的是旧基线。

**隔离真实工作流复现：** 旧基线序列 AGLK，保留旧 review_id/base_revision=1；发布同 record_id、序列 GGGG 的新基线并更新发布指针。旧请求 reject 成功，写入 GGGG revision 2，而应拒绝为基线冲突。

**修复条件：** 审核身份及唯一约束包含基线，不允许旧 review_id 被重绑定；命令携带期望基线并在同一事务内校验；旧 open 项保持 superseded，历史决定不变。回归必须使用真实 build_review_plan 和发布路径，不手工编造两个不同 review_id 来绕过问题。

### S02 [P1] 对比重试会重复执行同一侧

**位置：** `src/bio_pdf/application/comparison_service.py:128–142`、`:200–210`。

执行线程按启动时读取的状态快照决定哪些侧需运行；retry 在原线程仍运行时再启动线程，没有原子的侧领取或 lease。

**隔离服务复现：** 阻塞 Docling，调用 retry，使另一线程完成 MinerU，再放开原线程。调用序列为：

```text
['docling', 'mineru_http', 'mineru_http']
```

原线程仍依据旧 queued 快照再次执行 MinerU。固定侧目录还会被覆盖；真实环境可能重复发起云任务。

**修复条件：** 对比侧通过持久化队列/lease 原子领取，完成发布校验 side/attempt token；有效 running 状态不可由 retry 重复领取；每次 attempt 使用独立不可变目录与制品引用。测试并发 retry 和 stale worker 完成路径。

### S03 [P1] 再次复解析覆盖历史候选

**位置：** `src/bio_pdf/api/routes/results.py:936–940`。

每次写同一个 `candidate_ocr.txt`。两次 OCR 分别返回 candidate-1/candidate-2，第二次后，第一次事件的 artifact_rel 仍指同一文件，而内容已变成 candidate-2。事件日志不能重现当时的候选。

**修复条件：** 为每次候选/attempt 建立唯一身份和目录，记录内容哈希与原基线、页区、引擎参数。第二次解析不得改变第一次事件所引用的内容；采用候选也必须建立新的正式基线并保留历史。

### S04 [P1] issue 操作没有验证其所属任务

**位置：** `src/bio_pdf/api/routes/results.py:728–735` 的 `_issue_or_404` 及其 action/reparse 调用。

只按 issue_id 查找，没有校验 row.job_id 与路由 job_id。对有效任务 B 请求任务 A 的 issue action，得到 200 且 A 被 dismissed。reparse 还会使用 B 的 PDF 配合 A 的页码，并把候选挂到 A 的历史，造成证据串任务。

**修复条件：** 按 job_id+issue_id 查询并检查关联基线；不匹配返回 404/明确冲突且零写入。候选源文档、源 SHA、页区和事件所属任务必须一致。覆盖读、动作、复解析全部入口。

### S05 [P2] API 重启后 running 对比侧无法恢复

**位置：** `src/bio_pdf/application/comparison_service.py:123–133`、`:205–206`。

当前依赖进程内 daemon 线程，retry 仅重排 failed/queued，执行时跳过 running。

**真实子进程复现：** 对比执行中退出进程；新进程 retry 后仅执行另一侧，原侧永久 running，整体无法结束。

**修复条件：** 结合 S02 使用可恢复 worker/lease；过期 running 可安全重领，已完成侧不重复执行。用独立子进程重启测试，不能只在同进程重建 service 对象。

**Standards 轴补充：** D01 新的单事务及异常 rollback 路径未发现新的确定缺陷。本轴不另列纯启发式代码风格问题。

## 四、方案覆盖与数据语义审查（Spec）

### P01 [P1，D02 残余] 不同位置的相同 OCR 行仍被删除

**位置：** `src/bio_pdf/workflow/handlers.py:864–884`。

相邻 OCR 文本相等就删除后一个，不比较位置；原生/OCR 对齐又仅比较 y 区间，无法区分同一高度的不同栏位。

**本轮主审直接复现：**

```text
输入 OCR：[(100,110,'ACGT'), (200,210,'ACGT')]
输出：1 块 ['ACGT']，conflicts=[]
```

相同的序列行在不同位置可以是真实重复内容，不能丢失。仅 y 重叠还会把另一栏的不同文本记为冲突并移出提取流。

**修复条件：** 保留完整二维 bbox、源、序列区域与顺序；只对同一物理提及做内容一致合并，不同位置的重复行全部保留；不同粒度的原生段落与 OCR 行不得仅因 y 重叠就判冲突。新增同内容异位置、同 y 异栏、段落/行粒度及相同位置差异回归。

### P02 [P1，D03 残余] 单处页眉证据仍能删除全文正文残基

**位置：** `src/bio_pdf/extract/sequences/st25.py:539–554`、`:588`。

虽然开始检查几何/角色，但证据按文本全局保存；某一处同文本出现在 header，就把其他所有位置的同文本加入全局黑名单。

**本轮主审直接复现：** 三页正文分别声明 SEQ 1/2/3，各有 `Ala Cys 2`，本来得到 3 条 AC；再加第四页同文本 header：

```text
BODY_ONLY_RECORDS 3
AFTER_HEADER_RECORDS 0
恢复长度 [None, None, None]
```

**修复条件：** 排除依据绑定每个块/行的实际位置和角色；重复文本只能辅助判定，不能全局屏蔽字符串。测试同文页眉+正文、正文多编号、多处同残基及实际 EP 页眉。

### P03 [P1，D07 新实现] 对比任意配对有歧义的活性，制造虚假差异

**位置：** `src/bio_pdf/application/comparison_service.py:472–507`。

匹配 key 仅为 entity/metric/target，缺少实验条件；虽然计算 ambiguous 数量，但随后又用字典覆盖多候选并比较最后一项。

**隔离复现：** A/B 两侧均为 `{MIC 1µM@1h, MIC 2µM@2h}`，仅数组顺序相反。结果 `paired=0, ambiguous=1`，却还报告 `value_a=2, value_b=1` 的假差异。

**修复条件：** 领域摘要保留方法/时间/浓度等条件及证据上下文；按规范化条件参与候选分组；仅两侧均唯一的候选进入字段比较，歧义返回候选集合，不做字典覆盖。结果对输入顺序应不敏感，并用 Decimal/单位语义区分数值差异与格式差异。

### P04 [P1，D07 未完成] 真实页尺寸与 bbox 坐标制式未完整贯通

**位置：** `src/bio_pdf/parsers/mineru_adapter.py:1341–1362`。

新增真实尺寸元数据，但 bbox 仍原样复制，没有明确处理坐标单位、旋转/裁切变换或拒绝未知坐标。

**隔离投影复现：** A4 `(595,842,90)` 与 bbox `[0,0,1000,1000]`，归一化仍保留同一越界坐标。更换页面宽高并不等于已校验区域位置。

**修复条件：** 按实际响应 schema 明确 bbox 的基准/单位/旋转；转换到源 PDF 可见页面点坐标并校验边界；信息不足标未知或明确拒绝，不能推断为已验证。真实云端尚未成功，此项是投影路径可复现缺口，不声称已证明某个远端响应必定采用某种单位。

非连续页的绝对/相对 page_idx 语义仍需真实协议制品核实；本轮不把未证实的云端索引约定作为额外确定缺陷。

### P05 [P1，D08 未完成] 来源对照展示融合块，缺失实际原生和 OCR 来源

**位置：** `src/bio_pdf/api/routes/results.py:229–240`；`web/src/features/tables/TableView.tsx:459–472`。

接口只返回 normalized 融合结果，通道回退还不认识实际的 `native_text`；前端只把这些块分桶，没有展开或读取被融合消耗的原始来源。extract 阶段的区域 OCR 也未进入这些视图。

**真实制品核对：** `job-c6d96cb945d2` 第 32 页原生 27 块、Docling 13 块；融合结果为 27 块，其中 13 Docling、14 native_text。API 将后 14 块误标为 layout，另 13 个原生原始块不能单独查看。全文任务的区域 OCR 残基也不能在三视图中对照。

**修复条件：** 原始块/来源对照从各引擎真实制品读取，并保留已融合来源的映射；认识全部正式通道名；区域 OCR 保存为可审计制品并接入按页读取。阅读展示可以融合，但来源对照必须能查看各自原始文本。多栏/跨栏标题、段落间距和短词导致整段 cellLike 的旧合并限制也需继续回归。
