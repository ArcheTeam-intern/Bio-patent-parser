# 引擎选型评估：怎么评判，以及当前结论

日期：2026-10-19
评估脚本：`scripts/eval_engines.py`
原始数据：`reports/eval_engines_20261019.json`
本机扫描结果：`out/eval_scan.json`

## 1. 评判方法（回答"怎么评判"）

### 1.1 不要跑全文

`pdf/` 里 9 份文档，页数 2–195。全文双引擎跑一遍既慢又贵，且大部分页与产品目标无关（权利要求、说明书套话）。抽样规则：

1. 本地扫描每份 PDF，标出**含 ST.25 标记（`<210>`/`<211>`）的页**和**含 MIC/IC50 表头的页**；
2. 每份只跑这些页 + 首页（结构基线），6 页以内；
3. MinerU 侧通过 `page_ranges` 只解析请求页，云端成本与页数成正比。

扫描结果（`out/eval_scan.json`）：

| 文档 | 页数 | ST.25 页 | MIC/IC50 页 |
|---|---:|---|---|
| paper_TAT-RasGAP | 12 | 无 | 2–10 |
| CN114144196B（中） | 57 | 从 25 起，15 页 | 无 |
| EP3027649B1 | **195** | 从 30 起，60 页 | 4–27 |
| EP3423477B1 | 68 | 从 29 起，20 页 | 7–26 |
| US20240026005A1 | **142** | 无 | 无 |
| US5459060A | 37 | 无 `<210>`；用 `SEQ ID NO` 旧格式 | 无 |
| WO2017060493A1 | **167** | 无 | 无 |
| WO2020156367A1（中） | 25 | 无 | 无 |
| WO2021207200A2 | 99 | 无 | 无 |

**重要边界**：`US5459060A` 用的是 `(2) INFORMATION FOR SEQ ID NO:4:` 旧格式且是扫描 OCR 文本（`Lic u As n Al a T r p`），当前产品只支持 `<210>` 格式，这类文档不在评估范围。

### 1.2 指标（按产品价值排序）

| 指标 | 定义 | 为什么排这个位置 |
|---|---|---|
| **残基恢复率** | Σobserved_length / Σdeclared_length | 序列是产品核心价值；恢复不出来等于没解析 |
| **完整声明数** | inventory `complete` | 一条完整序列比三条 partial 有用 |
| **表格可用率** | 通过结构闸门的表 / 检出表 | 检出但 12×392 崩坏的表是负价值 |
| **成功率** | 成功运行次数 / 总次数 | 稳定性是底线 |
| 耗时 | 墙钟 | 次要，但影响体验 |

表格可用率只统计通过 `GRID_SIZE_SUSPECT` / `RAGGED_ROWS_SEVERE` / `HEADER_SEMANTICS_BROKEN` 的表——把崩坏表算作"检出成功"会奖励伪造网格的解析器。

### 1.3 必须声明的限制

**没有人工 gold。** 所有数字都是覆盖率/一致性，不是准确率。当前样本 4 份文档，不足以推出统计结论。要下最终结论至少需要：10+ 份同类型专利、每份人工标注序列和关键活性值、按字段算召回与精确率。

## 2. 本次实测结果

抽样：CN114144196B 页 {1,25,26,27}、EP3027649B1 页 {4,6,30,31,32,33}、US20240026005A1 页 {1,2,30}；加上之前已跑的 EP3423477B1 页 {23,24,26,29,30,31,32}。

### 2.1 序列

| 文档 | 语言 | Docling | MinerU |
|---|---|---|---|
| EP3027649B1（195 页） | 英 | **0 条** | **8 条，全部 complete，恢复率 1.0** |
| EP3423477B1（68 页） | 英 | **0 条** | 1 条 partial（293/549） |
| CN114144196B（57 页） | 中 | **2 条 partial（恢复率 0.497）** | **0 条** |
| US20240026005A1（142 页） | 英 | 无序列 | 无序列 |

**结论：英文专利 MinerU 完胜（9 条 vs 0），中文专利 Docling 更好（2 vs 0）。**

中文侧根因已定位（`cmp-46ad5f7ec23a`）：

- Docling 保留行级结构：`<210> 3`、`<210> 4` 各自独立 block，12 个残基块；
- MinerU 把整段合并：`[0084] <400> 4 [0085] atgaacg...` 变成一个大 block，只剩 2 个残基块，声明行被吞进段落。
- 即 MinerU 在中文段落式排版下**过度合并**，行级结构丢失。

### 2.2 表格

| 文档 | Docling | MinerU |
|---|---|---|
| EP3027649B1 页 4/6 | 1 张，可用 | 0 张 |
| US20240026005A1 页 1/2/30 | 0 张 | 2 张，可用 |
| EP3423477B1（之前） | 2 张（漏 TABLE 2/3） | 4 张（2 张崩坏，被闸门拦下） |

两侧互有漏检，**没有单侧赢家**。MinerU 检出更多但结构崩坏率更高；Docling 检出少但结构准确。

### 2.3 稳定性与成本

| 项 | Docling | MinerU |
|---|---|---|
| 成功率（本次 3 份） | 3/3 | 3/3 |
| 平均墙钟（同页范围） | 80.5 s | 80.5 s（两侧并行，受 Docling 拖累） |
| 独立耗时（12 页论文） | ~100 s | ~50 s |
| 外部依赖 | 无（本地模型 0.55 GB） | token + 网络（VPN/DNS 一错整侧失败） |
| 数据出境 | 否 | 是 |
| 成本 | 0 | 按页计费 |

历史失败记录：MinerU 因 Meta VPN 劫持 CDN DNS 失败 2 次（SSL EOF），因 Docling sparse 页段 identity 碰撞失败 1 次（已修）。

## 3. 选型建议

### 3.1 推荐：按语言路由，MinerU 为主

理由：语料 7 英 2 中；英文专利序列恢复 MinerU 9:0，这是产品核心能力。Docling 在英文专利上一条序列都解析不出，不能做主力。

```
主引擎   = mineru_http      （英文文档）
降级引擎 = docling_sdk      （MinerU 不可用 / 中文文档 / 需要表格交叉验证）
路由规则 = 文档语言检测 → 中文走 Docling，其余走 MinerU
```

### 3.2 降级触发条件

1. MinerU 未配置（`configured=false`，capability 已支持）；
2. MinerU 连续失败（网络/额度）；
3. 文档语言为中文（MinerU 行级结构丢失）；
4. 结构化闸门拦下 MinerU 的表格，且该表是本次任务的目标 → 用 Docling 重跑该页做交叉验证。

### 3.3 不建议的方向

- **不要二选一后删掉另一个**：两侧的失败模式不同（MinerU 中文合并、Docling 英文序列丢失），保留降级路径的成本低于丢失核心能力的成本。
- **不要用品格数量直观判断**：MinerU 检出 20 个 figure 不等于更好（子图级别 + caption 归属混乱）；Docling 检出 9 个整图，caption 归属更清晰。

## 4. 下一步（要把结论钉死还需要什么）

1. 把样本扩到 10+ 份英文专利 + 5 份中文专利，每份抽 6–8 页；
2. 对序列做**逐字符**人工核对（至少 3 份），得出真正的召回/精确率；
3. 对表格做单元格级核对（至少 5 张），区分"漏检"和"结构错"的损失；
4. 补中文路由的语言检测实现（当前 `_effective_remote_params` 只按 `ocr_lang` 选项，不自动检测文档语言）。

在此之前，本文的结论定性为**方向性判断**，不是最终选型依据。
