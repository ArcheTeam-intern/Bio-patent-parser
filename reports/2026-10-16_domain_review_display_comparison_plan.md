## 二、序列完整性与序列—活性关联

### 2.1 关系模型

```text
序列或序列片段
      ↓ 组成 / 链 / 连接子 / 变体
被测实体：肽、蛋白、抗体、构建体、化合物
      ↓ 在某实验中被测
活性结果
      ├─ 指标、数值、单位
      ├─ 靶标或菌株
      ├─ 方法、浓度、时间等实验条件
      └─ 字段级原文证据
```

不限制一条序列对应一项活性。同一实体可以对应不同实验条件下的多项结果；完整抗体的结果可以通过抗体实体关联到重链和轻链，但不能宣称这些组成链分别具有同样的活性。

`Measurement.sequence_ids` 保留直接序列关联。通过构建体、重轻链或片段间接关联的序列，通过关系图与角色表达，不混成直接被测序列。

### 2.2 建立序列清点表

清点表先于残基识别完成建立，每个声明编号保留一行：

- 文档、SEQ ID、声明长度、分子类型；
- 声明位置、残基区域、续页区域与证据；
- 是否在本次请求范围内；
- 恢复长度、识别来源、状态及缺失/冲突原因。

固定状态：

| 状态 | 含义 |
| --- | --- |
| `declared` | 找到声明，尚未恢复残基 |
| `partial` | 仅部分恢复，或被请求页边界截断 |
| `complete` | 已恢复，且长度、字母表、来源检查通过 |
| `conflict` | 来源、长度或残基存在冲突 |
| `missing` | 请求范围内应存在的残基未恢复 |
| `outside_scope` | 不在本次请求范围 |

前端分别统计声明数、已定位数、完整恢复数、部分/冲突/缺失/范围外数量。不得用候选条数代替完整性。

全文 EP 验收应清点出声明的 82 个编号；前 40 页只报告其自身范围的覆盖情况。相同残基内容但不同 SEQ ID 的清单项仍保留独立编号。

### 2.3 ST.25 与混合区域识别

1. 先把同块中的 `<210>…<211>…<212>…` 切成独立标签事件，再解析字段；SEQ ID 只接收编号。
2. `<400>` 后进入残基状态，支持计数列、三字母氨基酸、60 字符 DNA 行及跨页续接；遇下一标签或明确区域边界结束。
3. 通过几何位置、版面角色和跨页重复识别页眉、页脚、侧边行号；保留原始块供审计，禁止页眉进入残基。
4. 有 `<400>` 或明确声明但残基为空/明显不足时，检查渲染区域，加入初次 OCR 执行计划；不能仅用整页字符数决定是否需要 OCR。
5. 原生和 OCR 结果分别留证据；一致时合并来源，冲突时保留双方及位置。
6. 初次识别后仍失败的区域进入现有有界复解析计划，记录预算和失败原因。
7. `MMP`、`CDR` 等短字符串必须结合序列引导语和上下文判断，不能只凭氨基酸字母表认定为序列。

重点验收：第 32 页 SEQ ID 7 的声明长度为 364，残基区域需要被实际识别；长度吻合也不代替逐字符正确性验证。

### 2.4 有证据的实体与关系

完善现有实体和关系模块，支持明确分子名、`#134` 等专利编号、表格实体名、别名、链、CDR、连接子和变体。

关系来源仅限明确的原文、表格、图题及相互引用；关系证据必须在索引中真实登记。当前以字符串拼出的关系证据 ID 要替换为可解析的实际 span。

关联状态区分：已关联、有歧义、序列缺失、范围外、不适用序列关联、未找到证据。

抗生素等非序列实体可以具有活性，不应统一要求序列。目标生物分子的实验结果与背景药敏数据保留分类，前端可分别筛选。

构建体关系需要保留修饰、方向及连接证据。W317A 涉及编号坐标和方向，不能在未核对坐标体系时自动改写片段。

### 2.5 展示与验收

记录接口扩展返回实体、关系、实验信息和序列覆盖摘要；旧字段保持可读。序列详情增加关联实体与结果，活性详情增加被测对象和关联路径。

关联表：

> 被测对象｜关联角色｜序列编号/片段｜指标｜数值与单位｜靶标｜条件｜证据｜状态

验收场景：

- 同一实体对应多个指标或条件；
- 抗体的重轻链组成关系；
- 同一区域两个片段；
- 同内容不同 SEQ ID；
- 请求范围外的引用；
- 非序列实体无需序列；
- 无明确证据保持未关联；
- 本论文的两个片段、GG 连接关系、构建体和 W317A 变体分别存在，且不冒充已确认完整链。

## 三、审核去重、分组与规则修正

### 3.1 三层处理

| 层级 | 方案 |
| --- | --- |
| 同一物理提及被多个通道重复提取 | 合并记录，保留各来源证据 |
| 同一记录重复生成审核项 | 计划及数据库写入幂等 |
| 同一区域有多个合法结果 | 展示为审核组，保留独立子项 |

不按相同 bbox、相同数值或相同原因直接删除记录。去重依据包括文档/页码、单元格或文本偏移、指标、实体、靶标、条件，以及序列修饰与作用域。

### 3.2 校验规则

- 使用指标注册表的单位要求；分类药敏 S/R/I 不再产生“缺少浓度单位”。
- MIC、IC50 等需要单位的数值结果继续检查。
- 原因使用稳定代码，具体消息放详情，避免依赖英文自由文本分组。
- 通用“需人工核对”作为状态说明保留，不重复堆叠同义原因。
- 保持当前 `pass/fail/unknown` 契约；无需单位的检查可返回 pass，并在详情说明不适用，不把正常分类值当缺失。

### 3.3 分组展示和独立决定

默认按“任务及基线 → 表格/区域 → 子记录”展示；分别显示待审核记录数和组数。

```text
第 8 页 · 药敏表 · 192 条待核对结果
  ├─ Vancomycin → Staphylococcus capitis：S
  ├─ Vancomycin → Staphylococcus aureus：S
  └─ ……
```

子项展示实体、靶标、值、指标、单元格/原文片段。折叠不等于自动确认。

批量决定需显式勾选子项，每项携带版本；全部预检查后统一提交，任一冲突整体失败，并保留逐记录决定日志。

### 3.4 幂等与迁移

审核身份绑定 `job_id + baseline_id + record_id + record_revision`，增加相应唯一性保证。

新基线替代旧基线时，旧未完成项标记为被替代，不能伪装成人工确认。迁移先列出疑似重复项；确切同记录重复可以合并原因和证据，不按区域合并不同记录，不抹除历史人工决定。

前端摘要/缓存键包含任务、基线、记录版本，避免相同文档的不同任务互相覆盖摘要。

验收：重试、恢复、重复发布不增加重复开放项；共享区域的合法结果仍独立存在；审核版本冲突仍返回明确冲突，不能静默覆盖。

## 四、逐页图表、原文阅读与问题详情

### 4.1 图表按页

- `FiguresTab` 接收当前页与范围，默认当前页，全文需显式切换。
- 同时显示当前页与全文数量。
- 点击卡片定位对应页及 bbox；查看大图/下载为独立动作。
- 增加 `GET /jobs/{job_id}/figures?page_number=N`，保留不带筛选参数的全文读取兼容性；返回基线、筛选结果和文档总数。
- 缓存键包含任务、基线及页码。
- 未生成、损坏、没有图表分别展示；不能把所有 WorkflowError 吞掉后显示空列表。

### 4.2 原文三种视图

| 视图 | 规则 |
| --- | --- |
| 原始块 | 当前页全部原始块、原始顺序与来源，不改写原文 |
| 阅读顺序 | 按版面组织段落，并保留原始块映射 |
| 来源对照 | 展示原生、结构引擎/OCR 的差异 |

阅读顺序由归一化层生成，替代前端仅按“相邻同类型/角色”合并：

1. 优先保留引擎有效阅读顺序。
2. 多栏识别栏位、跨栏标题和独立区域。
3. 合并同时检查栏位、间距、缩进、角色和区域边界。
4. 标题、图题、正文、表格、清单、序列分开处理。
5. 一个短词不能把整段变成标签；连字符处理只改变阅读展示。
6. 表格吸收的块在阅读视图提供“转到表格”，原始块视图仍完整保留。
7. 顺序不确定时明确标记，保留逐块入口。
8. 序列等宽显示，保留分行、计数和不确定残基。

### 4.3 问题详情

每条问题包含严重程度、页码/区域、关联对象、实际与期望、原因、影响、原文、来源、建议动作及历史。

示例：

> **序列残基未恢复**：第 32 页，SEQ ID 7，声明 DNA 长度 364。文本层能读取标签，未恢复残基；渲染区域存在序列。影响是完整性未知，暂不能导出完整 FASTA 或建立确认序列关联。建议对该区域 OCR，并核对长度及字符。

“评分表”“菌株目录”通常为提示；残基缺失、长度和结构冲突为警告/错误。“无目标结果”和“识别失败”分别表达。

问题接口支持页码、严重程度、状态过滤；位置来自真实来源对象，不从不透明 ID 猜页号。

### 4.4 可执行动作

实现：定位原文、请求区域复解析、标记非目标并填写原因、保留未解决并添加说明。

复解析产生独立候选制品和前后差异，经明确采用后发布新基线；沿用租约校验与有界预算。前端仅在后端实际可用时展示可操作按钮。

### 4.5 验收

- 翻到第 2 页仅展示该页图表；无图页如实为空。
- 图表、原文、表格与 PDF 共用页码，URL 刷新可恢复。
- 多栏不交错，标题/图题不混入正文。
- 原始块内容完整，阅读改写可追溯。
- 证据自动进入可见区域。
- 缺失、范围外、未解析、损坏分别提示。
- 问题卡能回答“为什么、影响什么、下一步怎么办”。

## 五、Docling 与 MinerU 云 API 对比

### 5.1 已确定的部署选择

用户明确选择：**沿用 MinerU 云 API**，本轮不建设 MinerU 自建推理服务。

核查进程中的本地版本：Docling `2.138.0`、docling-core `2.101.1`、RapidOCR `3.10.0`、ONNX Runtime `1.31.0`。首轮冻结本地版本，MinerU 默认 `vlm`；记录真实请求参数。云端未返回具体模型版本则记为未知，不声称完全可复现。

本次核查进程没有读取到 `MINERU_TOKEN`。执行前检查 API 与 worker 的实际环境；Token 仅由服务端环境/配置读取，禁止写入前端、提交或报告。未获得可用环境时完成适配和可审查制品，并将真实云实测明确列为未完成，不伪造结果。

### 5.2 真实引擎分派

- 按有效配置调用对应 adapter，统一 capability、API、配置和 worker 的引擎名称。
- MinerU 不可用时明确失败，不静默调用 Docling 并标记成 MinerU。
- manifest 记录实际引擎、参数、版本及原始响应引用。
- 首轮对比关闭额外跨引擎融合，使用各引擎输出和相同领域规则，避免补齐掩盖差异。

### 5.3 修正文件上传协议

```text
验证本地源 SHA-256
  → POST /api/v4/file-urls/batch
  → 保存 batch_id、data_id、上传槽位
  → PUT 文件
  → GET /api/v4/extract-results/batch/{batch_id}
  → 按本文件身份找到结果
  → 下载结果包并归一化
```

官方说明：文件上传后自动提交解析，应按批次查询。当前“把 PUT 签名 URL 当公开 PDF URL 再提交”的流程必须替换。

要求：

- 源哈希验证发生在上传之前。
- 页范围、语言、表格和 OCR 参数真正传入云端。
- 持久化远端身份以恢复轮询，避免重试重新创建任务。
- 上传/结果下载客户端不携带平台 API Token；签名 URL 查询参数不进入普通日志。
- 明确处理认证失败、限流、超时和远端失败。

依据：[MinerU 官方接口文档](https://mineru.net/doc/docs/index_en/)。实施时再次核对协议并记录核对日期。

### 5.4 归一化修复

- 根据响应 schema 识别协议，优先读取有页码/结构的结果。
- 使用源 PDF 真实页尺寸、旋转和坐标映射，不统一假设 612×792。
- 保存表格行列/合并格、图表区域及图题。
- 页码转换保留明确映射，校验实际返回页集合。
- 只有 Markdown 时标记缺少逐页结构，不把全文塞进一个虚构页面。
- 页缺失、页异常、协议不支持分别报错。

### 5.5 对比接口、任务与页面

新增：

```text
POST /comparisons
GET  /comparisons/{comparison_id}
GET  /comparisons/{comparison_id}/diff
```

创建输入：已登记文档、请求页集合、两边引擎配置、共同领域规则版本、可选人工标注集。

固定保存源 SHA-256、配置快照、版本与制品引用；两边通过队列独立执行，可分别失败、重试和查日志。

实验任务不向正式审核队列自动注册大量审核项，但保留建议审核数量和验证结果。采用实验结果时显式建立正式结果基线。

页面包含：

1. 运行概况：版本、参数、页覆盖、状态与分阶段耗时。
2. 解析差异：文本、阅读顺序、表格、图表、序列区域。
3. 领域差异：序列、活性、实体、关系及未解决项。
4. 原文证据：共用 PDF，并列记录和高亮。

差异分类：一致、仅 Docling、仅 MinerU、字段不同、匹配有歧义。

匹配规则：

- 清单按文档与 SEQ ID；正文序列结合页码、区域和上下文。
- 活性按被测对象、指标、靶标、实验条件建立候选。
- 唯一候选自动配对，多个候选保留歧义。
- 数值和单位是待比较字段，不加入匹配键造成值差异只能被报告为两侧缺失。
- 不直接使用两次运行生成的记录 ID 对齐。

### 5.6 样本、标注和指标

| 样本 | 范围与目的 |
| --- | --- |
| TAT-RasGAP 论文 | 全文 12 页；片段、构建体、变体、药敏矩阵及图表 |
| EP3027649B1 | 局部调试 30–40 页；完整性验收全文 195 页 |
| WO2020156367A1 | 全文 25 页；中文扫描 OCR |

标注分为全文编号/位置清点、重点残基逐字符标注、活性元组、实体关系和明确负例。标注必须独立核对原文，不能直接使用某个引擎输出作为 gold。

| 层级 | 指标 |
| --- | --- |
| 覆盖 | 请求页、实际页、遗漏页 |
| 序列 | 检出、完整字符串精确匹配、残基编辑错误、误报、清单完整率 |
| 活性 | 实体/指标/值/单位/靶标/条件元组 |
| 关系 | 正确、错误、未关联、歧义 |
| 结构 | 单元格和图表区域匹配 |
| 审核 | 无效原因、重复提取、记录数与组数 |
| 运行 | 排队、上传、解析、后处理耗时及成功/失败数 |

无 verified gold 的范围仅展示差异、覆盖与数量，准确率为 `not_evaluated`。双方一致不等于正确，结果更多不等于效果更好。现有长序列近似对齐不得冒充精确字符错误率。
